# Langues du site

La boutique s'affiche en anglais (`en`, langue par défaut), en français (`fr`) ou en créole haïtien (`ht`). Les URL ne changent pas : la langue suit le visiteur, pas l'adresse.

## Comment la langue est choisie

1. Le cookie `clag_locale`, posé uniquement quand le visiteur choisit une langue (sélecteur dans l'en-tête, ou dans le menu sur mobile). Il dure un an.
2. Sans cookie : anglais.
3. À la connexion, la langue enregistrée sur le compte (`users/{uid}.preferredLanguage`) revient dans le navigateur. Un compte sans langue enregistrée reprend celle choisie dans le navigateur.

Changer de langue en étant connecté l'enregistre aussi sur le compte : le choix suit le client sur ses autres appareils.

## Où sont les textes

- `i18n/messages/{en,fr,ht}/` : un fichier par domaine (`shell`, `home`, `catalog`, `shop`, `emails`, `base`). L'anglais est la référence : TypeScript refuse un dictionnaire français ou créole auquel il manque une clé.
- Côté serveur : `const { t } = await getI18n()` (`i18n/server.ts`).
- Côté client : `const { t } = useI18n()` (`i18n/client.tsx`).
- Les deux exposent aussi `plural`, `price`, `number`, `date`, `dateTime` et `message` (un message de validation transmis sous forme de clé).
- Clé absente à l'exécution : texte anglais, puis la clé elle-même, avec un avertissement dans la console. La page ne casse jamais.

## Formats

| Langue | Montant BSD   | Date longue       |
| ------ | ------------- | ----------------- |
| `en`   | `B$1,234.50`  | `2 November 2026` |
| `fr`   | `1 234,50 B$` | `2 novembre 2026` |
| `ht`   | `1 234,50 B$` | `2 novanm 2026`   |

`Intl` n'a pas de données pour le créole : `ht` utilise les conventions haïtiennes (`fr-HT`) pour les nombres, et ses propres noms de mois. Toutes les dates suivent le fuseau de Nassau. Une ancienne commande en HTG reste affichée en HTG.

## Erreurs et e-mails

- Une erreur destinée au client est une `UserError` (`i18n/user-error.ts`) : elle porte une clé, et l'action serveur la traduit. Son texte (`message`) reste le français d'origine, pour l'administration et les tests existants. Une erreur interne n'est jamais montrée telle quelle : le client voit un message générique.
- La langue est enregistrée sur la commande (`orders.locale`). Les e-mails de commande (confirmation, paiement, expédition, livraison, remboursement) et les SMS s'écrivent dans cette langue. Une commande plus ancienne, sans langue enregistrée, garde ses e-mails en français.
- Les e-mails de Firebase (vérification d'adresse, mot de passe oublié) sont demandés dans la langue du visiteur. Firebase n'a probablement pas de modèle créole : il utilise alors son modèle par défaut.

## Ce qui n'est pas traduit

- Le contenu saisi par les gens : noms et descriptions des produits, des boutiques et des catégories, bannières, titres de sections de l'accueil, menus personnalisés. Les menus et la description de la boutique d'origine, jamais modifiés, sont traduits ; un texte saisi par un administrateur est affiché tel quel.
- Le Seller Center, l'administration et les pages client qui ne font pas partie du sprint i18n-1 : commandes, retours, liste de souhaits, candidature vendeur, pages À propos, FAQ, contact, mentions légales, livraison et retours, collections, comparateur. Elles restent en français, sous un en-tête et un pied de page traduits.

## Ajouter une page traduite

1. Ajouter les textes dans les trois dictionnaires (TypeScript signale ce qui manque).
2. Remplacer les chaînes par `t("…")`.
3. Ajouter le fichier à `MIGRATED` dans `i18n/i18n.test.ts` : le test refuse un texte français écrit en dur.
